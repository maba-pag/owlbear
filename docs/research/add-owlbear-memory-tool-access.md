### Validation compatibility (S3)

`validate_agents.py` accepts MCP wildcard patterns via `name.endswith("/*")`. Adding `'owlbear-memory/*'` to any agent will pass validation.

### Critical finding: mcp.json registration missing (S5)

`.vscode/mcp.json` currently registers only 3 servers: `microsoft/markitdown`, `owlbear-kanban`, `owlbear_knowledge`. The `owlbear-memory` server is NOT registered. Without this, the tool patterns in agent frontmatter are inert—VS Code cannot route calls to a server it doesn't know about.

**This is a hard blocker for #568's intent** (making get_knowledge/record_learning calls work). The agent frontmatter edits are still valid to do now (they won't break anything), but they won't take effect until mcp.json is updated.

### Secondary finding: setup.py naming inconsistency (S6)

setup.py uses camelCase keys (`owlbearKanban`, `owlbearMemory`) while the workspace mcp.json uses kebab-case (`owlbear-kanban`, `owlbear_knowledge`). Agent tool patterns use kebab-case (`'owlbear-memory/*'`). Consumer projects generated by setup.py would have mismatched keys vs tool patterns.
