# Brief — Expectation Fidelity Scenario

## Proposal

Add expectation fidelity to the ideation workflow so qualitative user expectation survives discovery, mediation, Brief approval, and task planning.

## Binding Product Promise

The approved Brief is the binding product promise. Everything listed here is required unless a later decision records an accepted trade-off.

## Expected Experience

An ideation run should leave the user feeling that the agent understood the result they wanted, not just the smallest task set that could satisfy a checklist. The artifacts should preserve what the user is actually trying to get, what would make it worth using, what can arrive first, what remains, what would be technically done but still wrong, and what the user knowingly gave up.

## First Release Is Not The Promise

The first releasable slice may add Expectation Signal capture and the pre-Brief expectation-fidelity Critic check. That slice is useful, but the workflow is not complete until tier-scaled M2 checks, Brief binding, and planning preservation are also represented.

## Passable-But-Wrong Result

A workflow that asks for a minimum viable result, drafts a checklist Brief, and creates tasks without carrying the user's desired experience forward is explicitly rejected. That result is taskable, but it is not the promised product.

## Requirements

- Discovery captures the contrastive Expectation Signal.
- The First Useful Step remains sequencing, not replacement scope.
- O15 evaluates whether challenged items are wanted, not merely necessary for bare function.
- Planner sequences or splits Brief requirements but does not delete them.
- Planning output shows how the expected experience remains covered, or returns the trade-off to the user.

## Out Of Scope

- Creating a new value-preserver agent in this revision.

## Runtime Validation

Live validation on the main-consuming runtime is still required.
