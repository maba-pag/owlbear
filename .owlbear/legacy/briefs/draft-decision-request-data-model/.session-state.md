## Key Design Summary (for Brief)

### Model Shape
- Two kinds: `decision` | `action`
- Request ID: UUID4 (filename = `{request_id}.md`)
- Storage: YAML frontmatter + markdown body
- Directories: `decisions/pending/` and `decisions/resolved/`

### Fields
- `request_id`, `task_id`, `kind`, `title`, `summary`, `created_at` (ISO 8601 w/ TZ), `agent`
- `options[]` (decision-only, ≥2 required): `option_id` (slug, max 63), `label` (max 120), `confidence` (0.0-1.0), `recommended` (bool), `rationale` (max 500)
- Resolution: `status` (approved/rejected/needs-info for decisions; done/rejected/needs-info for actions), `selected_option_id` (required on approved), `free_text` (always optional), `resolved_by`, `resolved_at`
- Body markdown for extended context

### Engine API (3 operations)
- `create_request()` — validates, writes file atomically, blocks task
- `resolve_request()` — validates resolution, rename-as-check atomicity, writes ID-tagged summary to task body, conditional unblock (sibling check)
- `list_requests()` / `get_request()` — read operations

### Architecture
- Single engine writer (no other layer writes files)
- Pydantic `extra="forbid"` with kind-discriminated validation
- MCP tools: `create_request`, `list_requests`, `show_request` (no resolve tool)
- Cockpit API: list pending, resolve (adapted controls)
- Sweep kept as crash-recovery fallback only
- Resolved files immutable

### Resolution Flow
create → task blocked → user resolves in Cockpit (approved/rejected/needs-info OR done/rejected/needs-info) → resolution written to file → renamed to resolved/ → ID-tagged summary appended to task body → task unblocked (if no sibling pending) → agent sees resolution

### Expectation Signal
- Promise: Real choice system (option cards, free text, mechanical flow-back)
- First Useful Step: Model + engine + MCP/API, THEN Cockpit UI + agent instructions
- Technically Wrong: raw text rendering, no free text, no flow-back, regex extraction, internal interfaces, dead fields, outdated instructions

### Explicitly Excluded
- Threaded conversations, multi-user routing, recurring requests, multi-select, rich attachments, resolved browsing
- MCP resolve tool (deferred with gate conditions)
- Quick-confirm mode (deferred)
- Parallel request blocking semantics (unspecified)
