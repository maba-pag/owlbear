A memory field rename or removal crosses one producer-consumer boundary. `serve/cockpit/src/owlbear_cockpit/routes/memory.py::_to_response` validates `MemoryEntryResponse` from `entry.model_dump()`. The response fields have no defaults, so removing a `MemoryEntry` field breaks the Cockpit API immediately. `serve/cockpit/web/src/pages/MemoryTab.tsx` and the assembled e2e spec `e2e/memory-lifecycle-assembled.spec.ts` read the same field. Keep the model, Cockpit API, web type and UI, and e2e fixtures and specs in one task. Splitting the Python work from the web work leaves the first task's contract inconsistent, and planner-challenger rejected that split for memory-revision-binding OUT-003.
