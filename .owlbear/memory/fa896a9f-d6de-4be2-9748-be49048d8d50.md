After PortfolioApplication began reconciling runtime membership from persisted discovery (serve/delivery/src/owlbear_delivery/delivery_contract_discovery.py `_parse_admission`/`_cross_validate`), any hand-assembled Delivery fixture must write admission.json alongside contract.json and frontier.json or the Change is observed as unadmitted Design. A valid fixture receipt requires contract_digest == contract_fingerprint(contract), source_bindings_digest over the sorted compact JSON of contract.source_bindings, frontier_ids equal to the frontier binding plan_scope_ids, and a receipt_id that is sha256 of the canonical payload excluding receipt_id; construct it via DeliveryAdmissionReceipt.model_validate so a wrong digest fails at fixture build instead of silently changing the observed lifecycle. Check both e2e seeds (serve/cockpit/web/e2e/support/) and manual MCP test fixtures, since they omit it independently.
