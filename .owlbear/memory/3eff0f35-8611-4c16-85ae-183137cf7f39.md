Knowledge MCP has no serve/knowledge-mcp/tests directory; its assembled-tool tests live under root tests/ (e.g. tests/test_mcp_knowledge_static_refresh.py provides _assembled_context via server.build_app_context and _FailingPersistenceConnection that fails 'FROM content_documents' reads). Adding a code to the closed KnowledgeFailureCode Literal in serve/knowledge/src/owlbear_knowledge/protocols/failures.py breaks tests/test_knowledge_failure_contract.py, which asserts the exact get_args tuple, so any task adding a failure code must own that test as a maintained surface.
