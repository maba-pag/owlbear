When reviewing a task chain, verify each control named by an acceptance observation is rendered after the preceding action, not merely that it exists somewhere in the UI. Read the enclosing render condition and ensure the prior state makes it reachable. For example, `serve/cockpit/web/src/pages/MemoryTab.tsx` renders `clear-filters` only when `hasEntries && !hasVisibleEntries`; an observation that filters to still-visible matches cannot activate it. The maintained `serve/cockpit/web/e2e/memory-state-filter.spec.ts` demonstrates the reachable no-match path before clicking it.
