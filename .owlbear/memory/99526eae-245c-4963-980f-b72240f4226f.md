tests/test_package_boundary.py builds its package map from `serve/*/src/owlbear_*` and checks only files under those roots, so a cross-package import that appears solely in `serve/<pkg>/tests/` cannot trip the allowlist. When reviewing a plan that places an adapter import in another package's test module, the boundary argument must instead be checked against the consuming package's declared dependencies (e.g. serve/delivery/pyproject.toml lists no owlbear-delivery-github) and the invocation environment, not against that regression test.
