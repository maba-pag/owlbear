After `/finalize-change` returns `review_failed` with an implementation finding, readiness only offers "Retry verification" on the same head, and `repair_completed_outcome` needs an engine-issued finalization attempt that no tool exposes. To fix it while keeping task evidence, follow the external-head adoption path in `w-delivery-attention-resolution`, but only after the user explicitly chooses adoption. Commit the fix on a descendant of the reviewed head, push it to `owlbear/change/<id>`, call `adopt_external_head`, then re-run finalization, which promotes the adopted head after an exact review. `adopt_external_head` can return `ERR_DELIVERY_PROVIDER_CONFLICT` from its trailing state publication even though the receipt and branch move were recorded. Re-read coordination before any retry. Cockpit's backward move instead clears the outcome's tasks and evidence.
