Adding a pytest marker to root pyproject.toml addopts does not isolate it, because any command-line `-m` replaces the addopts selection entirely. At the OwlBear repository root the maintained explicit `-m` selectors are .github/workflows/dependency-verification.yml (its 'Run Python behavior tests' step, pinned character-exact by tests/test_dependency_verification_workflow.py) and the '(no prefix match)' fallback row of the Test Domain Mapping table in .github/copilot-instructions.md. Other runners rely on addopts: .github/workflows/agent-ecosystem.yml invokes pytest with no `-m`, and `uv run test` builds `uv run pytest <targets>` in serve/tools/src/owlbear_tools/testing.py without any marker expression. When reviewing a plan that introduces an opt-in marker, require an owning task for each of those explicit selectors or an explicit recorded exclusion.
