Cockpit's detail route (`TargetCockpitService.show_item` in `serve/cockpit/src/owlbear_cockpit/routes/target_work.py`) calls `show_work_item_view` and returns `WorkItemDetailView` (`serve/delivery/src/owlbear_delivery/work_items.py`, built by `WorkItemProjector.show_view`). It never reads `DeliveryChangeView` (`get_change`). A Change-level field meant for Cockpit must be projected on `WorkItemDetailView` (as `pause_available` and `revision_prompt` are); `DeliveryChangeView` embeds it as `detail`, so MCP `get_change` sees it too. `tests/test_cockpit_boundary.py::test_work_item_detail_view_typescript_parity` requires every `WorkItemDetailView` field to have a top-level mirror in the `WorkItemDetailView` interface of `serve/cockpit/web/src/api/workItems.ts`.
