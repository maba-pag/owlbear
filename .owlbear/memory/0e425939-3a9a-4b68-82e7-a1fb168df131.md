title: SQLite connections in MCP lifespans forbid asyncio.to_thread store calls
unremarkable_count: 0
updated_at: '2026-09-03T15:54:43.869864+00:00'
---

In an MCP server, a lifespan-owned `sqlite3.connect()` defaults to `check_same_thread=True`; wrapping a store call in `asyncio.to_thread()` then raises `sqlite3.ProgrammingError` because the call runs on another thread, while mocked-store tests can pass. When reviewing such tools, inspect every `asyncio.to_thread` call against the connection's thread setting and prove it with a real connection, not only mocks.
