title: sqlite3 connections in MCP lifespans forbid asyncio.to_thread store calls

In serve/knowledge-mcp/src/owlbear_knowledge_mcp/server.py the lifespan builds sqlite3.connect(db_path) without check_same_thread=False, so any tool that wraps a store call in asyncio.to_thread (register_source did until dc0c534) raises sqlite3.ProgrammingError in production while mock-based tool tests still pass. When reviewing MCP tools backed by a lifespan-owned sqlite3 connection, check every asyncio.to_thread call against the connection's check_same_thread setting instead of trusting mocked-store tests.
