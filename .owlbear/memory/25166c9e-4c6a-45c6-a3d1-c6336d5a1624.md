When reviewing a Delivery finalization merge, the commit message's `# Conflicts:` list is not the risk surface. Run `git show --cc <merge>` to find files whose merged content differs from BOTH parents — those are silently auto-merged blends where one side's production change (e.g. dev adding `--locked` in serve/tools/src/owlbear_tools/testing.py) can invalidate the other side's untouched assertions (serve/tools/tests/test_testing.py). Verified on merge 0ca310249feb5be47810ff97ac2848fb72163d68, where the only `--cc` hunk was in a file absent from the recorded conflict list and absent from the exact-head proof command.
