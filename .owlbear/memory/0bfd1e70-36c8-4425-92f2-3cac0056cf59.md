`parse_delivery_frontier` in `serve/delivery/src/owlbear_delivery/delivery_runtime.py:3442` raises a bare `TypeError` when the decoded frontier payload is not a JSON object and a bare `ValueError` when `schema_version` is not 17, before it ever reaches `DeliveryFrontier.model_validate_json(..., strict=False)`. Any consumer migrated from a direct `model_validate_json` call must widen its `except` clause from `ValueError`/`ValidationError` to include `TypeError`, otherwise non-object frontier JSON escapes the existing failure route (as at `delivery_application_loader.py:487-495`). Because both exceptions carry no message, error-classification helpers that inspect `str(error)` — such as `_snapshot_validation_code` at `delivery_state.py:629` — fall through to their generic branch.
