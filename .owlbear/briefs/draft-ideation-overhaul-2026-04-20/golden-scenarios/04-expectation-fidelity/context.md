# Context — Expectation Fidelity Scenario

## Problem

The user wants the ideation workflow to stop turning a high-quality desired product into the smallest technically passable implementation.

## Expectation Signal

### What are we actually trying to give the user?

A workflow that preserves the product promise from discovery through Brief and task planning, so a complete desired result does not collapse into a bare minimum implementation.

### What would make it feel worth using?

- The agent captures qualitative expectation in the user's own terms, then keeps that expectation visible during decisions.
- The final Brief reads like a product promise, not a reduced checklist.
- The task plan decomposes the Brief while preserving the part that makes the outcome satisfying: the user can still recognize what they asked for after planning turns it into work.

### What can arrive first without pretending it is finished?

The First Useful Step can be a first release that adds Expectation Signal capture plus the pre-Brief expectation-fidelity Critic check. It must ship with a visible remaining-promise note: tier-scaled M2 checks, Brief binding, post-planner expectation-fidelity review, and planning preservation still need to land before the workflow is complete.

### What would be technically done but still wrong?

A Brief that says only "ask for minimum viable result and create tasks" would pass a narrow process check but still preserve the old failure mode. It would produce taskable work without preserving the user's desired experience.

### What did the user knowingly give up?

No new value-preserver agent in this revision. Existing Critic and conditional end-user review carry the expectation-fidelity work.

## Tier

Shared.

## Current Tensions

- Keep the contract strong without spreading detailed rules into every agent.
- Let planner decompose work without making planner responsible for product taste.
